# Documentation

Four kinds of document live here, and they age differently. **Guides** and
**references** describe Curatarr as it is now and are updated with the code.
**Design records** explain why something was built the way it was.
**Audit reports** are dated snapshots: their line numbers, counts and
"open" items describe the commit they name, not today's code.

When two documents disagree, trust them in this order: the code, then
[SECURITY.md](../SECURITY.md) and [ARCHITECTURE.md](../ARCHITECTURE.md),
then the guides, then [CHANGELOG.md](../CHANGELOG.md), then everything
else.

## Audit reports — dated snapshots

Each report names the commit it read. Fixes landed after it, and the
reports carry dated status notes where they were revisited. For what is
true today, read the code and the documents above. The regression suites
named in each report keep its fixes pinned.

| Report | Scope | Regression suite |
|---|---|---|
| [security/appsec-audit-2026-10-10.md](security/appsec-audit-2026-10-10.md) | Endpoints, sessions, the deletion path, outbound clients, secrets. Its draft `url_policy.py` became `src/services/endpoint_policy.py` | `tests/test_appsec_2026_10.py` |
| [SQLITE_ASYNC_CONCURRENCY_AUDIT.md](SQLITE_ASYNC_CONCURRENCY_AUDIT.md) | Sessions, PRAGMAs, the scheduler, database calls on the event loop (2026-10-11) | `tests/test_loop_db_ratchet.py` (and `src/database/loop_guard.py` at runtime) |
| [POST_REFACTOR_INTEGRATION_AUDIT.md](POST_REFACTOR_INTEGRATION_AUDIT.md) | Whether the 2026-10 workstreams fit together: JSON contracts, migrations, residual blockers (2026-10-15) | `tests/test_integration_audit_2026_10.py` |
| [SILENT_FAILURE_SWEEP_2026_10.md](SILENT_FAILURE_SWEEP_2026_10.md) | Every audit against the live code, and every `except` that hid a failure (2026-10-15) | `tests/test_silent_failures_*.py`, `tests/test_silent_except_ratchet.py` |
